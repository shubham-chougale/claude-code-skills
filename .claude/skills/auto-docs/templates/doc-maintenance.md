## On Every Git Commit

When a commit is detected, scan the diff and apply the following rules:

### Automatic Updates (no human needed)

| File Pattern Changed | Action |
|----------------------|--------|
| `routes/` `controllers/` `api/` `endpoints/` `views/` | Update `/docs/architecture/API.md` — append/update changed endpoint |
| `migrations/` `*.sql` `*_migration.*` | Update `/docs/architecture/DATABASE.md` — add migration entry + update schema table |
| `package.json` `requirements.txt` `Podfile` `build.gradle` `go.mod` | Update `/docs/deployment/SETUP.md` — update dependency list |
| `.env.example` | Update `/docs/deployment/SETUP.md` — update env variables table |
| `src/components/` `components/` | Update `/docs/components/[ComponentName].md` — update props/usage |
| `src/modules/` `modules/` `src/services/` | Update `/docs/modules/[ModuleName].md` — update public interface |
| Any file | Append entry to `/CHANGELOG.md` |

### Diagram Flags (human updates the diagram, Claude flags it)

| File Pattern Changed | Diagram Flagged |
|----------------------|-----------------|
| New directory in `src/` or root | `system-architecture.html` — "New module/service detected" |
| `routes/` `api/` `controllers/` | `sequence-diagram.html` + `api-lifecycle.html` — "API change detected" |
| `migrations/` | `erd.html` — "Schema change detected" |
| `infra/` `terraform/` `*.yml` in deploy | `deployment-topology.html` + `cicd-pipeline.html` — "Infra change detected" |
| `.github/workflows/` `Jenkinsfile` `*.ci.yml` | `cicd-pipeline.html` — "Pipeline change detected" |

### Document Flags (human updates the doc, Claude flags it)

| Trigger | Document Flagged |
|---------|-----------------|
| New feature directory or module | `HLD.md` — "Architecture may need updating" |
| New API endpoint | `FRD.md` — "FRD may need new requirement" |
| Major refactor commits | `LLD.md` — "Module design may need updating" |
| `docker-compose.yml` or `Dockerfile` change | `INFRA.md` — "Infrastructure doc may need updating" |
| Pipeline config changed | `CICD.md` — "Pipeline doc may need updating" |

## On Every Pull Request

When a PR is opened or updated, run a staleness check:

1. Detect the type of change from the PR diff
2. Look up affected documents using `change_impact_map` in `settings.json`
3. Check if each affected document has been updated in this PR
4. If a document is not updated and it is affected by the change:
   - Post a PR comment: "⚠️ **Doc update needed:** `[document path]` — this change affects [document name]. Please update before merging."
5. Do not block the merge. Only flag.

## Sprint End Audit

At sprint end, compare every document's `last_updated` header against the current code state:

```
For each document in DOC_OWNERS.md:
  1. Read last_updated from the document header
  2. Calculate days since last update
  3. If days > staleness_threshold_days (from settings.json):
     → Flag as stale
  4. For API.md: compare endpoints in doc vs endpoints in codebase
     → Flag any undocumented endpoints
  5. For DATABASE.md: compare tables in doc vs migration history
     → Flag any undocumented tables
  6. For CHANGELOG.md: check entries match git log since last entry
     → Flag any missing entries
```

Output the Stale Doc Report:

```
📋 Doc Audit Report — Sprint [N] — [Date]

✅ Up to date: [list docs]
⚠️  Needs update: [doc name] — [reason why]
❌ Missing: [doc name] — [why it should exist]

Action required: [count] items
```

## On Every Release

When a release branch is created or a version tag is applied:

1. Read `/CHANGELOG.md` — extract all entries since the last release tag
2. Auto-generate `/docs/releases/v[version].md` using this format:
   ```
   ## v[version] — [Date]
   ### What's New
   [feat: entries from changelog]
   ### Improvements
   [chore: entries from changelog]
   ### Fixed
   [fix: entries from changelog]
   ```
3. Snapshot all docs into `/docs/releases/v[version]/archive/`
4. Update version references in `/docs/architecture/API.md`
5. Notify: "Release notes generated at `/docs/releases/v[version].md` — please review before publishing."

## Safety Rules (Never Break These)

- Never delete content from any document — only append or update
- Never overwrite a human-written section with auto-generated content
- Never auto-edit BRD, SCOPE, ROLLBACK, INCIDENT_RESPONSE, POSTMORTEM
- If unsure which document to update — flag it, do not guess
- Always show what will be written before writing to a document
- Diagrams are never auto-edited — only flagged with a specific reason
