👋 What Is This Project?

This isn't a typical app with a backend and a frontend. It's a Claude Code workspace — a curated collection of custom skills that turn Claude Code into a specialized engineering assistant for AI/GenAI work.

Think of it as a developer toolkit shipped as Claude commands. Instead of building separate CLIs, dashboards, and scripts for everyday engineering tasks, this project packages them as Claude skills you invoke with a slash command. Type /get-trending-in-AI in Claude Code and you get a full AI radar report. Type /auto-docs init and a complete documentation system is generated for your project.

It currently ships four production-ready skills, all designed around real engineering pain points: trend discovery, frontend design, database migrations, and automated documentation.

So basically — this is a "skills library for Claude Code" that turns one-off engineering tasks into reusable slash commands.

🏗️ Tech Stack

There's no server, no React app, no database here. The "stack" is the Claude Code skill format plus a handful of supporting technologies for the artifacts skills produce.

🔄 How A Skill Runs

The end-to-end flow when a user types a slash command:

User types /skill-name in Claude Code
           ↓
Claude Code resolves to .claude/skills/skill-name/
           ↓
Loads SKILL.md (instructions) and settings.json (config)
           ↓
Reads frontmatter (name, description) — registers as invocable
           ↓
Executes the workflow defined inside SKILL.md:
  • Reads relevant project files
  • Calls scripts in /scripts/ if defined
  • Performs web searches (if pre-allowed)
  • Generates output (markdown, HTML report, or interactive prompts)
           ↓
Writes the output file(s) and optionally auto-opens them
           ↓
Updates settings.json (e.g., dedup database for trend skill)

Two important properties: (1) skills have no shared state — each is self-contained and (2) skills can mutate their own settings.json to track history across runs (dedup, version, etc.).

So basically — slash command → SKILL.md is the playbook → Claude follows it → outputs land on disk.

🤖 AI Discovery Deep Dive

This is the most AI-relevant skill for your role. Let's open it up.

The problem it solves: AI moves fast. New frameworks, new models, new patterns drop weekly. Manually browsing GitHub trending, Twitter, and changelogs is a part-time job. This skill automates the discovery.

How it's architected:

SKILL.md
  ├── Pre-Generation Deduplication Check    ← Mandatory first step
  ├── Focused Execution Mode                ← Strict scope rules
  ├── Interactive Menu (7 modes)            ← User picks discovery focus
  │     1. Newly Released AI Frameworks
  │     2. New Models & Research Breakthroughs
  │     3. Industry-Changing Launches
  │     4. Trending GitHub Repos
  │     5. Production-Ready GenAI Patterns
  │     6. Future Trends & Upcoming Releases
  │     7. Custom Discovery
  ├── Per-Option Output Spec (strict)       ← What to generate per mode
  └── Discovery DB Update Rules             ← How dedup state is maintained

settings.json
  └── discovery_database
      ├── discoveries[]                     ← Every tracked item with ID
      ├── by_framework{}                    ← Search indexes
      ├── by_category{}
      └── metadata                          ← Total tracked, last updated

The discovery flow:

User invokes /get-trending-in-AI
       ↓
Load settings.json → show existing discoveries by category
       ↓
User picks mode (1-7) and optional filters (top N, last X days)
       ↓
Claude searches the web with scoped queries
       ↓
For each discovery found:
   • Generate ID (e.g., "langgraph-1.2.0")
   • Check against existing IDs in database
   • If exact match → SKIP
   • If major evolution → ADD as new entry with flag
   • If new → ADD
       ↓
Generate focused HTML report (only selected mode's content)
       ↓
Auto-open report in browser
       ↓
Update settings.json with new discoveries (dedup state grows)

Key things to study as an AI engineer:

  • The focused execution mode — it's a great pattern for keeping LLM outputs scoped and token-efficient (cuts ~40% tokens vs naive prompting).
  • The dedup ID strategy — uses framework name + version as canonical ID. Major evolution flag handles version bumps cleanly.
  • The per-option output specs — each mode has a strict "GENERATE / SKIP" contract. This is how you stop LLMs from sprawling.
So basically — it's a focused, stateful AI research agent that grows smarter every time it runs because the dedup DB accumulates institutional memory.

📄 Auto-Docs System

The newest and biggest skill — worth understanding because it shows how a Claude skill can scaffold a full system, not just generate output.

What it does: Generates 26 document templates, 9 interactive Mermaid diagrams, and 4 hook layers (git, Claude, CI, audit) for a new project. After init, docs maintain themselves automatically.

The 4 hook layers — this is the interesting architecture:

LayerWhere It LivesFires OnWorks Outside Claude?
Git hooks.githooks/git commit, git push✅ Yes
Claude Code hooks.claude/settings.jsonPostToolUse, Stop⚠️ Only in Claude sessions
CI / PR check.github/workflows/doc-check.ymlPR opened/updated✅ Yes
Sprint auditscripts/audit_docs.pyOn demand / cron✅ Yes

The layers overlap on purpose — if git hooks miss a commit pushed from a different machine, CI catches it on PR. If CI is bypassed, the sprint audit reports it later. Defense in depth for documentation.

The change → doc mapping (defined in settings.json as change_impact_map):

new_feature      → USER_STORIES, FRD, API, DATABASE, HLD, TEST_CASES, RELEASE_NOTES, CHANGELOG
api_change       → API, FRD, TEST_CASES, RELEASE_NOTES, CHANGELOG
db_schema_change → DATABASE, TEST_CASES, RELEASE_NOTES, CHANGELOG
infra_change     → INFRA, DEPLOY, CICD, RUNBOOK, CHANGELOG
bug_fix          → TEST_CASES, CHANGELOG, RELEASE_NOTES, RUNBOOK

The diagrams are 9 interactive HTML files using Mermaid.js. Each has a rendered diagram pane plus an editable source pane — users edit the Mermaid code and re-render in-browser. Never auto-edited by Claude, only flagged.

The entry point: When a developer wants Claude to update docs, they say:

"Check .claude/hooks/hooks.md and apply the doc maintenance for this change."

That single file is the master guide — Claude reads it, follows the routing rules, updates the right docs, flags the right diagrams.

So basically — one init command sets up a self-maintaining documentation system with 4 overlapping safety nets. The hooks.md file is the door Claude walks through.

🎯 Your Personalized Roadmap

You're an AI Engineer — your value here is going to come from understanding the AI-focused skill deeply and then building new ones. Here's how I'd pace your first month.

Week 1 — Get Fluent With Claude Code Skills
  • Read CLAUDE.md, SKILLS_INVENTORY.md, and .claude/skills/README.md end to end.
  • Run each of the four skills once. Pay attention to the interaction pattern, not just the output.
  • Study how SKILL.md + settings.json work together. Open one skill folder and trace what files are read and what files get written.
  • Understand the difference between .claude/settings.json (global) and .claude/settings.local.json (overrides).
Week 2 — Master the AI Discovery Skill
  • Open .claude/skills/get-trending-in-AI/SKILL.md and read every section. Notice the "Focused Execution Mode" — this is gold for any AI engineer building prompted systems.
  • Study the discovery database structure in settings.json. Understand how dedup IDs are constructed and how major-evolution flags work.
  • Read DEDUPLICATION_GUIDE.md. The algorithm there is reusable for any agent that needs to avoid repeating itself.
  • Run /get-trending-in-AI a few times across different modes and watch how settings.json grows.
Week 3 — Understand The Auto-Docs Architecture
  • Read .claude/skills/auto-docs/SKILL.md, then CLAUDE.md, then settings.json in that order.
  • Open templates/hooks/hooks.md — this is the pattern for "Claude as a maintenance agent." Study how the 4 hook layers interact.
  • Read the four Python scripts in templates/hooks/scripts/. They're short, stdlib-only, and show how to bridge git events and Claude behavior.
  • Open one of the 9 diagram HTML files in a browser. Notice the editable-source-plus-rendered-output pattern — useful for any "AI-generated artifact" skill.
Week 4 — Build Your Own AI Skill
  • Pick one repetitive AI engineering task you do (e.g., reviewing LLM eval results, drafting agent prompts, comparing model outputs).
  • Scaffold a new skill: mkdir .claude/skills/your-skill-name, then add SKILL.md + settings.json.
  • Use the existing four skills as patterns. The AI discovery skill is the closest reference if you're building something stateful with a database.
  • Test it. Document it in SKILLS_INVENTORY.md. Open a PR.

You're going to enjoy this codebase. It's small, opinionated, and every file is there for a reason. If you find yourself doing the same AI engineering task more than twice, that's a candidate for a new skill. Welcome aboard. 🚀
